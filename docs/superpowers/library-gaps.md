# Library gaps

Components or behaviors the screens needed that `@odessa-separator/ui` does not provide, and the workaround used.

| Screen | Need | Workaround |
| --- | --- | --- |
| HierarchicalSidebar (business unit > department > app tree) | Expandable/nested sidebar item (tree with `aria-expanded`, indentation, child group). `SidebarItem` owns its `<li><a>` so it cannot contain a nested `<ul>`, and has no expand state. | Flat `SidebarItem`s indented with `ml-*` per level; BU and department rows are `href="#"` + `role="button"` + `aria-expanded` toggling local state (Space key does not activate an `<a role="button">`). |
| MobileNav categories (unused `showCategories` feature) | Sidebar item that acts as a button (not a link). | `SidebarItem href="#" role="button" aria-pressed`, click handler calls `preventDefault`. |
| Sidebar / MobileNav / HierarchicalSidebar section titles | `SidebarNav` wraps children in a `<ul>`, but `SidebarSectionLabel` renders a `<p>`, so the library's own API produces invalid HTML (`<p>` as a child of `<ul>`). | Used `SidebarSectionLabel` as documented inside `SidebarNav`; no wrapper added (a `<li>` wrapper would not help keep the library styling contract). Needs a library fix (render `<li role="presentation">` or allow it outside the `<ul>`). |
| Shared SkeletonLoader (avatar/icon placeholders) | Circular skeleton shape; `rounded-full` is forbidden by the guard and `Skeleton` has no `shape` prop. | Circular placeholders render with the library Skeleton corner radius (square-ish). `animation` prop is ignored; the library owns it. |
| ConfirmationModal (admin delete flows) | Dismiss on overlay (outside) click, as the old modal did. | Not supported by `AlertDialog` (by design, safer for destructive actions); accepted. Cancel button / Escape still call `onCancel`. |
| ConfirmationModal | Warning tone (`tone="warning"`) styling and icon. | `ConfirmDialog` only has `destructive`; warning renders as a primary button, same as default. |
| BusinessUnitView / ApplicationDetails breadcrumbs | `BreadcrumbLink` renders a plain `<a>` and has no `asChild`/router integration. | `src/components/BreadcrumbRouterLink.tsx` wraps `BreadcrumbLink` with a real `href` and a `navigate()` click handler (modified clicks keep browser default). |
| UserManagement user form (business units, departments) | Multi-select for the business units and departments a user can access (with "Select all"/"Clear all" and a business-unit filter for departments). | `Fieldset` with a scrollable list of `Checkbox`es, a ghost `Button` for Select/Clear all and a `Select` to narrow departments by business unit. |
| UserManagement user form | Wider dialog: the old modal was `max-w-3xl`; `FormDialog` has no size/`className` prop and is fixed at `max-w-lg`. | Kept `FormDialog`; fields stack to one column on narrow widths and the dialog body scrolls. |
| UserManagement password fields | Password input with a show/hide toggle. | `InputGroup` + `InputGroupInput` + an icon `Button` (`aria-pressed`, constant label "Show password") in an `InputGroupAddon`. |
| NotificationManagement create form (Expires At) | Date-time picker / calendar. | Native `<Input type="datetime-local">` inside a `Field`. |
| NotificationManagement create form (Target Audience) | Segmented single-choice control (the old three scope buttons). | `Fieldset` legend "Target Audience" with three `Radio`s (same `name`); no multi-select needed (one target per notification). |
| AppManagement / NotificationManagement / FileBankManager create forms | Wider dialog (old modals were `max-w-2xl` / side panel `max-w-md`). | `FormDialog` (fixed `max-w-lg`); body scrolls. |
| FileBankManager upload | Side sheet / drawer (old upload panel slid in from the right). | `FormDialog` (no general-purpose Sheet in the library; `SidebarDrawer` is for navigation). |
| FileBankManager upload | Drop zone showing the selected file's name and size. | Native `FileInput` (drag and drop onto the control works) + `Field` hint "name (size)". |
| WorkflowBrainPage metrics (Memory items / Workflow steps / Unknown areas) | KPI tile with a leading icon (the old metrics had a FileText / GitBranch / Search icon). | `StatCard` (label + value) in an auto-fit grid; the decorative icons are dropped because `StatCard` has no icon slot. |
| WorkflowBrainPage "Workflow" tab | Ordered list of process steps that shows each step's free-form status text (`active` / `unclear` / `risky` / `optimized`). `Step` has no slot for a status badge and only `complete/current/upcoming/warning`; mapping `active` to `current` would put `aria-current="step"` on several steps. | Semantic `<ol>` of `Card`s with the step number in the title and a `Badge` (`danger` for risky, `accent` otherwise), as the old page did. |
| WorkflowBrainPage category list (desktop sidebar) | Vertical single-select list whose options have a name and a description line. `ToggleGroup` items are fixed-height single-line buttons in a horizontal strip. | `<ul>` of full-width `Button`s (`accent` when selected, `outline` otherwise) with `aria-pressed` and a constant label, `h-auto whitespace-normal` so the description wraps. On < lg the list is replaced by a `Select` (old mobile picker). |
| TopBar | Global search with rich results (title, description, launch). | Hand-composed result list of library Buttons; Combobox only supports label/value options. |
| NotFound | `EmptyState` `titleAs` only allows h2-h6, so the page cannot get its `h1` from the component. | Visually hidden native `<h1 className="sr-only">Page not found</h1>` above the `EmptyState` (title stays `h2`). |
